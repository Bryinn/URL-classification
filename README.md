# Outputs

## Code organization

The numbered entry points in [`scripts`](scripts) contain the leakage checks,
feature-selection algorithm, model training, and evaluation calculations.
Formatting and artifact writing are kept separately:

- [`leakage_output.py`](scripts/leakage_output.py): clean dataset CSV and leakage report.
- [`selection_output.py`](scripts/selection_output.py): feature-selection plot and JSON report.
- [`forest_output.py`](scripts/forest_output.py): prediction tables, metric reports, plots,
  and saved model.
- [`output_io.py`](scripts/output_io.py): shared JSON serialization.
- [`common.py`](scripts/common.py): dataset loading, paths, grouping, and shared constants.

The commands and generated file formats are unchanged. Run the small CPU-only
regression test with `python -m unittest discover -s tests`.

Every file in [`outputs`](outputs) is generated by the scripts in [`scripts`](scripts).
Run them in order to regenerate the outputs:

```
python scripts\01_remove_leaky_features.py   # optional: --url-only
python scripts\02_select_features.py         # needs a CUDA GPU (or pass --device cpu)
python scripts\03_train_random_forest.py
```

Conventions used throughout:

- **Label:** `is_phishing` / `true_label` = `1` means phishing and `0` means legitimate. The original dataset's `Result` column uses `-1` for phishing and `1` for legitimate.
- **Positive class:** phishing. Precision, recall and F1 refer to the phishing class unless stated otherwise.
- **Decision threshold:** a site is predicted as phishing when `prob_phishing >= 0.5`.
- **Splits:** identical feature rows (47% of the dataset are duplicates) share a `group_id` and are always on the same side of a split. The test set has no rows in common with the training set.

## Step 1: leakage removal (`01_remove_leaky_features.py`)

| File | Contents |
|---|---|
| `clean_dataset.csv` | The dataset after the leaky features are removed: one row per original sample (11,055), the 20 kept features, plus `is_phishing` (label), `group_id` (hash of the original 30-feature row; duplicate rows share the same id) and `split` (`train` or `test`). Every later step reads this file. Ignored by git. |
| `leakage_report.json` | Explains what was removed and why. `removed` lists each leaky feature with its category and reason. `kept` lists the remaining features. `exact_duplicate_rows` and `conflicting_label_vectors` give duplicate statistics. `diagnostics` gives each original feature's single-feature ROC-AUC (cross-validated) and mutual information with the label. `mode` is `default` or `url-only`. |

## Step 2: feature selection (`02_select_features.py`)

| File | Contents |
|---|---|
| `selected_features.json` | Result of recursive feature elimination ranked by SHAP values, using a GPU random forest (XGBoost) on the training split only. `selected_features` and `dropped_features` give the final choice. `ranking` lists every feature's elimination rank, initial mean SHAP value, mutual information and whether it was selected. `curve` gives the cross-validated ROC-AUC (mean and standard error) for each number of features. `best` and `chosen` give the best subset and the smallest subset within one standard error of it, which is the one used. |
| `feature_selection_curve.png` | Plot of cross-validated ROC-AUC against the number of features, marking the one-standard-error cut-off and the chosen number of features. |

## Step 3: Random Forest model (`03_train_random_forest.py`)

### Model

| File | Contents |
|---|---|
| `random_forest.joblib` | The trained scikit-learn `RandomForestClassifier`, saved as a dict: `{"model", "features", "positive_class"}`. Load it with `joblib.load(...)` and call `model.predict_proba(X[features])[:, 1]` to get the phishing probability. Ignored by git (~18 MB). |

### Raw results (one row per sample)

| File | Contents |
|---|---|
| `rf_test_predictions.csv` | Predictions of the final model on the held-out **test set** (2,214 rows). |
| `rf_train_oof_predictions.csv` | Cross-validated predictions for the **training set** (8,841 rows). Each row is predicted by a model trained on the other 4 folds, so the model never saw that row. Has an extra `cv_fold` column (1–5). |

Columns in both files:

| Column | Meaning |
|---|---|
| `row_index` | Row position in the original `Training Dataset.arff` (0-based) and in `clean_dataset.csv` |
| `group_id` | Duplicate-group id; identical original rows share it |
| `split` | `test` or `train_oof` |
| `true_label` / `true_class` | Actual label: `1` / `phishing` or `0` / `legitimate` |
| `predicted_label` / `predicted_class` | Model prediction at threshold 0.5 |
| `prob_phishing` / `prob_legitimate` | Predicted class probabilities (they add up to 1) |
| `correct` | `True` if the prediction matches the actual label |
| `outcome` | `TP`, `TN`, `FP` (legitimate flagged as phishing) or `FN` (phishing missed) |
| `cv_fold` | Only in the training-set file: the fold the row was predicted in |
| remaining columns | The values of the 10 selected input features (`-1` = phishing indicator, `0` = suspicious, `1` = legitimate indicator, as defined in the dataset documentation) |

### Metrics

| File | Contents |
|---|---|
| `rf_results_report.txt` | Readable report: the features and settings used, all metrics for the test set, the confusion matrix, a per-class breakdown, cross-validated training metrics (pooled and per-fold mean ± std), and the leakage comparison runs. |
| `rf_metrics_summary.csv` | One row per evaluation and one column per metric, for use in spreadsheets and plots. The evaluations are: `test_holdout` (the headline result), `train_cv_out_of_fold`, `cv_fold_1`–`cv_fold_5`, `cv_mean`, `cv_std`, and `reference: ...` (comparison runs, see below). |
| `rf_metrics.json` | All of the above in machine-readable form: `features`, `best_params` (tuned hyperparameters), `cv_roc_auc` (best search score), `test`, `train_cv_out_of_fold`, `train_cv_folds`, `feature_importance` and `leakage_references`. |
| `rf_confusion_matrix.png` | Confusion matrix for the test set. |
| `rf_feature_importance.png` | Random Forest feature importance (impurity-based) for the selected features. |

Metrics reported for every evaluation:

| Metric | Definition |
|---|---|
| `accuracy` | (TP + TN) / all samples |
| `balanced_accuracy` | Average of recall and specificity |
| `precision` | TP / (TP + FP): of the sites flagged as phishing, the share that really are |
| `recall` | TP / (TP + FN): the share of phishing sites caught (sensitivity, true positive rate) |
| `specificity` | TN / (TN + FP): the share of legitimate sites correctly let through |
| `npv` | TN / (TN + FN): negative predictive value |
| `f1` | Harmonic mean of precision and recall for the phishing class |
| `f1_macro` / `f1_weighted` | F1 averaged over both classes, unweighted or weighted by class size |
| `f2` | F-score that weights recall more heavily than precision |
| `false_positive_rate` / `false_negative_rate` | FP / (FP + TN) and FN / (FN + TP) |
| `mcc` | Matthews correlation coefficient (-1 to 1; 0 = no better than chance) |
| `cohen_kappa` | Agreement with the actual labels beyond what chance would give |
| `roc_auc` | Area under the ROC curve (uses probabilities, independent of the threshold) |
| `pr_auc` | Area under the precision-recall curve (average precision) |
| `log_loss` / `brier_score` | Quality of the predicted probabilities (lower is better) |
| `tp`, `fp`, `tn`, `fn` | Confusion-matrix counts |
| `n_samples`, `n_phishing`, `n_legitimate` | Size of the evaluated set |

### Leakage comparison runs

The `reference: ...` rows (and `leakage_references` in the JSON) retrain the **same** Random Forest with leakage put back in, to show how much it inflates the scores. **They are not the final model.**

- `all_30_features_random_split`: includes the leaky features, and duplicate rows can appear in both train and test.
- `all_30_features_group_split`: includes the leaky features, but duplicate rows are kept apart.
- `selected_features_random_split`: the selected features only, but duplicate rows can appear in both train and test.
